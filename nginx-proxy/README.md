# nginx-proxy (production TLS termination)

Reverse proxy sitting in front of the `frontend` and `backend` containers in
`docker-compose.prod.yml`. Terminates TLS on 443, redirects 80 → 443, and proxies:

- `/api/**`, `/actuator/**` → `backend:8080`
- everything else → `frontend:8080` (static SPA + client-side routing fallback)

## Certificates

- **`docker compose -f docker-compose.prod.yml up` (local / on-prem compose target)**: the
  `cert-init` one-shot service (`generate-self-signed-cert.sh`) generates a self-signed
  certificate into the shared `ssl_certs` volume on first run, and leaves an existing
  certificate untouched on subsequent runs.
- **Real cloud deployment (AC: "LetsEncrypt for cloud")**: replace the `cert-init` service with
  `certbot/certbot` pointed at the same `ssl_certs` volume, e.g.:

  ```yaml
  cert-init:
    image: certbot/certbot
    volumes:
      - ssl_certs:/etc/letsencrypt
      - certbot_webroot:/var/www/certbot
    command: certonly --webroot -w /var/www/certbot -d ${DOMAIN_NAME} --email ${LETSENCRYPT_EMAIL} --agree-tos --non-interactive
  ```

  and mount `/etc/letsencrypt/live/${DOMAIN_NAME}/fullchain.pem` /
  `.../privkey.pem` in place of the self-signed paths — nginx-proxy's own config is
  identical either way, only the cert source changes. Add a renewal cron/sidecar
  (`certbot renew`) for the cloud target; self-signed certs generated by `cert-init` are
  valid for 365 days and are not auto-renewed (dev/on-prem convenience target only).

## Config rendering

`nginx.conf.template`'s `__DOMAIN_NAME__` placeholder is substituted by the
`nginx-proxy-config-render` one-shot sidecar before `nginx-proxy` starts, mirroring the
`prometheus-config-render` / `alertmanager-config-render` pattern already used in
`backend/docker-compose.yml`.
