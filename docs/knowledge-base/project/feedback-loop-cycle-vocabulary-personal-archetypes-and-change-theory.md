# Feedback Loop Extension: Cycle Vocabulary, Personal Archetypes, and Change Theory

## What Is It?

[Feedback Loop Taxonomy: Substrate, Instance, Stage, and Symmetry](feedback-loop-taxonomy-substrate-instance-stage-symmetry.md)
maps the base shape of a cybernetic loop. This article extends that map with a fourth batch that
splits into four unrelated groups: everyday **cycle vocabulary** (virtuous circle, self-correction,
self-perpetuating, iterative improvement, circle), **human archetypes** naming a person's role
inside a personal-development instance of the loop (Prokopton, go-getter/striver, self-actualizer),
a roughly 40-verb cluster of near-synonyms for "change something," and **quality attributes**. Most
of this restates concepts already mapped elsewhere in this KB; two pieces are genuinely new.

## Why It Matters

Everyday language has far more words for "change" and "cycle" than the taxonomy has structural
slots, which makes it easy to assume every new term needs a new box. Most don't — they're register
or domain variants of concepts already placed. The value here is being able to tell quickly which
of a large vocabulary is genuinely new structure (a personal-development domain instance; the
first-order/second-order change distinction) versus which is just another name for something
already mapped (a virtuous circle is positive feedback; iterative improvement is iteration plus
improvement).

## How It Works

### Cycle vocabulary — mostly renamings of what's already mapped

| Term | What it actually is |
|---|---|
| **Virtuous circle / cycle** | **Positive feedback**, beneficial direction. [Closed-Loop Feedback and Amendment Mechanisms for Process Documents](closed-loop-feedback-and-amendment-mechanisms-for-process-documents.md) already documents positive feedback in the *harmful* direction (the broken-windows spiral) — a virtuous circle is the same mechanism running the good way instead. Same structure, opposite sign. |
| **Self-correction** | The defining *property* closed-loop control produces — reducing error without external intervention. Not a new mechanism; the outcome-side name for what "closed-loop control" already means. |
| **Self-perpetuating** | A separate axis from direction: whether the loop needs external re-triggering each cycle, or its own output triggers the next cycle automatically (autocatalytic). A virtuous circle *and* a broken-windows spiral are both self-perpetuating — one beneficial, one harmful. This describes *continuation*, not *quality*. |
| **Iterative improvement** | The compound of two terms already mapped: iteration + improvement. Continuous improvement's other name, not a new concept. |
| **Circle** | Informal synonym for loop or cycle — same abstract shape, no technical distinction. |

### Human archetypes — a fourth domain instance: personal development

These name a *person* occupying a role inside the loop, not a mechanism — alongside closed-loop
control (engineering), continuous improvement/PDCA (organizational), and quality management
(product/service quality), personal development is a fourth domain instance of the same abstract
feedback loop:

| Term | Role within the personal-development loop |
|---|---|
| **Prokopton** (Stoic Greek, προκόπτων — "one making progress") | The agent actively *inside* the loop, mid-cycle, consciously improving but not yet converged — the practitioner, not the mechanism |
| **Go-getter / Striver** | The motivational disposition fueling the *act* stage — a personality trait, not a system property |
| **Self-Actualizer** (Maslow) | The loop's long-run convergence state, realized in a person. Maslow frames this as ongoing rather than a finished endpoint, so it overlaps with Prokopton — the difference is emphasis: Self-Actualizer names the *achieved altitude*, Prokopton names the *act of climbing* |

### The verb list — four clusters, one genuinely new distinction

Rather than mapping ~40 near-synonyms individually:

| Cluster | Representative members | Maps to |
|---|---|---|
| **Precision adjustment** | tune, attune, fine-tune, calibrate, adjust, regulate, modulate, temper, moderate, tweak | **Refinement** — small, within-cycle corrections, differentiated only by domain register |
| **Contextual fit** | adapt, customize, tailor, match | **Adaptation** — see the dedicated breakdown below; not a single mechanism, and not the same as a self-improving loop despite the surface resemblance |
| **Multi-component alignment** | harmonize, coordinate, integrate, synchronize, correlate, systematize, reorganize | A genuinely new idea: **coordinating multiple loops or parts** so they don't conflict — a different problem than tuning one loop's own parameter, closer to QA's meta-level design discipline |
| **Structural change** | transform, redesign, redo, reconstruct, revamp, rework, reshape, remodel, refashion, restyle, convert, alter, modify, change | Not refinement — **redesigning the loop's own structure** rather than tuning a parameter within it |

The structural-change cluster is worth naming precisely: it's the exact distinction Watzlawick,
Weakland & Fisch draw between **first-order change** (adjusting within the existing system/rules —
tuning `mutationThreshold`) and **second-order change** (changing the system/rules themselves —
replacing the PIT gate with a different quality mechanism entirely). The "tune" cluster is
first-order; the "transform/redesign/rework" cluster is second-order — the real reason this verb
list has two different registers of intensity even though every entry superficially means "change
something." (The remaining verbs — improve, make improvements to, amend, refine — are direct
synonyms of trajectory descriptors mapped in
[Feedback Loop Extension: Evaluative Dimensions and Quality Disciplines](feedback-loop-evaluative-dimensions-and-quality-disciplines.md);
no new placement needed.)

### Adaptation: three domain-specific meanings, not one

"Adaptive" gets used loosely to mean "self-improving" or just "responsive." At first principles,
**adaptation is a change in a system's behavior or internal model made in response to a change in
the environment or context it operates in** — distinct from ordinary correction, which responds to
a gap between output and a *fixed* reference under *unchanging* conditions. Three domain-specific
senses are worth telling apart:

| Sense | What updates | What stays fixed | Example |
|---|---|---|---|
| **Adaptive control** (control theory) | The controller's internal model of the plant's **dynamics** — see [Feedback Loop Substrate: Dynamics, Extrema, and Cyclical Process](feedback-loop-substrate-dynamics-extrema-and-cyclical-process.md#dynamic-more-primitive-than-cyclical-process) for the formal definition | The reference/goal | An autopilot recalibrating control gains as fuel burns off and mass shifts, while still targeting the same altitude |
| **Contextual adaptation** (the verb cluster above) | This cycle's output, tailored to a specific input | Nothing persists into the next cycle | A reflection loop tailoring a response to one user's phrasing |
| **Evolutionary adaptation** (biology) | Trait distribution across generations | The selection pressure defining "fit" | Differential survival and reproduction — the literal origin of the term **fitness function**, used throughout this taxonomy for the compare stage's reference metric |

**This resolves the loose "shared territory" claim in the table above.** Adaptive control keeps the
reference fixed and only updates the controller's model of its environment —
[Feedback Loop Extension: Enforcement and Safety Vocabulary](feedback-loop-enforcement-and-safety-vocabulary.md)'s
**self-improving loop** specifically updates the *reference itself*. These are not the same
mechanism: adaptive control is structurally closer to ordinary closed-loop control (same target,
better-informed correction) than to a self-improving/meta-loop (a different target each cycle),
despite "adaptive" sounding like it should mean the goal evolves too. It doesn't.

The evolutionary sense also closes a loop back to
[Quality Gate Ratchet Pattern](quality-gate-ratchet-pattern.md)'s "Is a Ratchet a Type of Evolution?"
section: adaptation in the biological sense is the general evolutionary process, and a ratchet
(Müller's, or the beneficial cultural one) is a specific irreversible sub-pattern that can appear
within it — the same relationship already established there, now connected through "adaptation"
rather than "evolution" as the linking term.

### Quality attributes

Extend the evaluative-dimensions category from
[Feedback Loop Extension: Evaluative Dimensions and Quality Disciplines](feedback-loop-evaluative-dimensions-and-quality-disciplines.md):
each individual quality attribute (latency, availability, security, maintainability, scalability,
usability) is a candidate fitness function for the compare stage, in the same slot as
efficiency/effectiveness, just domain-specific to software engineering. See
[mermaid-diagram-quality-attributes.md](mermaid-diagram-quality-attributes.md) and
[compliance-and-production-readiness-closed-loop-patterns.md](compliance-and-production-readiness-closed-loop-patterns.md)
for the dedicated treatment — this batch doesn't add a new placement beyond pointing at those.

## When to Use It

- Someone describes a positive spiral and reaches for a new term → check whether "virtuous circle"
  (positive feedback, beneficial direction) already covers it before inventing vocabulary.
- A person is described as "driven" or "still growing" in a process-improvement conversation →
  these are personal-development-domain roles (Prokopton, go-getter, self-actualizer), not new
  system mechanisms — useful for talking about people, not for designing gates.
- A proposed fix is described with a verb from the giant list → ask whether it's first-order
  (tuning a parameter within the current system) or second-order (redesigning the system itself)
  before estimating effort or risk — the two are not the same size of change even when the verb
  sounds similar.

## Examples

BuildNest's own PIT ratchet schedule is a **virtuous circle** in miniature: each milestone's higher
mutation score makes the codebase easier to extend safely, which makes the next milestone's target
easier to hit — the same self-reinforcing structure as a broken-windows spiral, running the
beneficial direction. Bumping `mutationThreshold` from 77 to 79 is **first-order change** (tuning a
parameter within the existing PIT-based quality mechanism); replacing PIT with a different mutation
testing tool entirely would be **second-order change** (redesigning the mechanism itself).

## Synthesis

Most of this batch is vocabulary, not structure — a virtuous circle is positive feedback with a
direction attached, self-correction is closed-loop control described from the outcome side, and the
~40-verb cluster mostly resolves into "refinement" once the domain-specific register is stripped
away. The two genuinely new pieces are worth remembering on their own: personal development as a
fourth domain instance (with Prokopton, go-getter, and self-actualizer as three different altitudes
within it, not three different mechanisms), and the first-order/second-order change distinction,
which is the real reason "tune" and "redesign" feel like different categories of effort even though
both are colloquially just "changing something."

## Quick Reference

| Question | Answer |
|---|---|
| Is a virtuous circle a different mechanism than positive feedback? | No — same mechanism, just the beneficial-direction instance; the KB already documents the harmful instance (broken-windows spiral) |
| Is self-correction the same as self-improvement? | No — self-correction (ordinary closed-loop control) corrects *output* toward a fixed reference; a self-improving loop updates the *reference itself*, one level of recursion higher |
| Is "tune" different from "redesign"? | Yes — first-order change (tune a parameter within the existing loop) vs. second-order change (redesign the loop's own structure) — Watzlawick's distinction |
| Are Prokopton, Go-getter, and Self-Actualizer three different mechanisms? | No — one domain instance (personal development), three different roles/altitudes within it |
| Is adaptive control the same as a self-improving loop? | No — adaptive control keeps the reference fixed and updates the controller's model of the environment; a self-improving loop updates the reference itself. Adaptive control is structurally closer to ordinary closed-loop control |
| Is "adaptation" one mechanism? | No — at least three: adaptive control (model updates, goal fixed), contextual adaptation (per-instance tailoring, nothing persists), and evolutionary adaptation (trait change via differential fitness) |
